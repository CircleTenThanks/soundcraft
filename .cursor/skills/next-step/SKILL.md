# 次の1コミット

`personal/ROADMAP.md` を読み、未了の番号を1つだけ実装する。終わったら、その差分のコミットメッセージをチャットに出す。`git commit` はしない。

## 手順

1. `personal/ROADMAP.md` の「作業の順番」と「コミットメッセージ」、および `AGENTS.md` を読む。
2. 利用者のメッセージに番号があればその番号を選ぶ。なければ「次の番号」を選ぶ。
3. `git branch --show-current` と `git status --porcelain` を見て、ロードマップの「ブランチとプルリク」と照合する。次のどちらかなら、実装に入らずブランチ名を1つ出して止まる。ブランチは切らない。
   - いまのブランチが `main`、または選んだ番号のブランチと違う。
   - 未コミットの変更が、選んだ番号と別の話題である。
   確認だけで製品コードを変えないと、始める前から分かっている番号では、ブランチを提案しない。
4. その番号の本文だけを実装する。前後の番号には進まない。確認だけで足りると書いてあり、問題がなければ製品コードを変えない。
5. ロードマップに無い数値、画面、操作を推測で足すことになるときは、実装を止める。足りない点を最大2つ、チャットで聞く。
6. 終わったら、選んだ番号の行末に `完了（YYYY-MM-DD）` を足し、「次の番号」を次の未了番号へ進める。日付は実行日。
7. 製品コードか文書に差分があるときは、下の形でメッセージをチャットの最後に出す。差分が「次の番号」の更新だけなら、結果だけ書き、メッセージは出さない。
8. 選んだ番号が、ロードマップの表でプルリクを出すタイミングなら、メッセージのあとに自分のフォークの `main` 向けの題名を1つ出す。上流の storytold/soundcraft 向けには出さない。プルリクは作らない。タイミングでなければ、プルリクには触れない。

## 守ること

- 品質、レイヤ、資産、パニック禁止は `AGENTS.md` に従う。
- 新しく書くコメントは日本語にする。上流の既存コメントと Markdown を、この作業のついでに訳さない。
- 画面の日本語は、英語のリテラルを残し、カタログで置き換える。
- テストしていない動作を、動いたと書かない。

## メッセージ

`personal/ROADMAP.md` の「コミットメッセージ」に従う。

```
type(scope): 件名

なぜこの変更が必要か。
```

件名は日本語の体言止めにする。末尾は「〜を追加」「〜を修正」「〜を変更」「〜を削除」のいずれかにする。「です」「ます」「しました」「した」「する」で終わらせず、句点を付けない。1行目は50文字以内。2行目は空行。本文には、なぜ必要かを書く。
