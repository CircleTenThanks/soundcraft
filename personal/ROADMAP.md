# 個人向けロードマップ

最終確認: 2026-10-16

このフォークは [storytold/soundcraft](https://github.com/storytold/soundcraft) を自分用に変えるためのものです。上流へはマージしません。上流の変更は、時々取り込みます。

作業は1コミット1話題に分けます。チャットで `/next-step` と指定すると、次の番号を1つ実装し、そのコミットメッセージを出します。ブランチを切るときと、自分のフォークへプルリクを出すときは、名前と題名を提案します。ブランチ、コミット、プルリクは、提案を見たあとで別に頼みます。

## 方針

日本語にしたい範囲は、画面、Markdown、ソースコードのコメントを含みます。取り込みを続けるため、置き場所を次のように分けます。

- 画面の文言は、英語のリテラルを残したまま、別ファイルの日本語カタログで表示を置き換えます。上流が英語の文言を直したときは、カタログのキーだけを追います。
- このフォークで新しく書くコメント、`personal/` の文書、Cursor のルールは日本語にします。
- 上流の Markdown を読みたいときは、`personal/ja/` に対訳を置きます。上流のファイルそのものは英語のまま残します。
- 上流の既存コメントをソース上でまとめて日本語へ置き換える作業は、最後に回します。取り込みのたびに衝突がファイル全体へ広がるためです。対訳で足りなくなった時点で、置き換えに進みます。
- パネル、フローティングウィンドウ、MIDI エディタ、スコア、サンプラーと、上流 Markdown の対訳は、操作バー以降の機能のあとです。

個人用の追加ファイルは `personal/`、`.cursor/rules/`、`.cursor/skills/` に置きます。上流に同名のファイルがないため、取り込みと衝突しません。

## コミットメッセージ

日本人の開発で広く使われている形に合わせます。Conventional Commits の type と、日本語の件名です。`/next-step` が実装の終わりに、この形でメッセージを出します。

```
type(scope): 件名

なぜこの変更が必要か。
```

- type は小文字の英字。`feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`chore`、`build`、`ci`。
- scope は任意。小文字の英数字と `.` `_` `-`。
- 破壊的変更は type の直後に `!` を付ける。
- 件名は日本語。何を変えたかが分かる対象を書き、体言止めにする。末尾は「〜を追加」「〜を修正」「〜を変更」「〜を削除」のようにする。
- 「です」「ます」「しました」「した」「する」で終わらせない。末尾に句点を付けない。
- 「修正」「追加」だけの件名にしない。
- 1行目は50文字以内を目安にする。超えたときは短くする。
- 2行目は空行。3行目以降に、なぜ必要かを書く。本文は1行72文字以内を目安にする。
- 絵文字は使わない。
- 1つのコミットに type が複数当てはまるときは、いちばん重要な変更で type を決める。

例。

```
feat(ui): 操作バーを画面下へ移動

編集中の手元に再生と停止を置くため。
```

`/next-step` はメッセージをチャットに出すだけで、コミットしません。

## ブランチとプルリク

プルリクの宛先は、自分のフォークの `main` です。上流の storytold/soundcraft へは出しません。

ブランチ名は `personal/` に、小文字の英数字とハイフンを続けます。`/next-step` は実装の前に、いまのブランチと未コミットの変更をこの表と照合します。`main` にいるとき、または表のブランチと違うときは、名前を1つ提案して実装を止めます。合っているときは提案しません。プルリクは、表のタイミングだけ題名を提案します。ブランチの作成、プッシュ、プルリクの作成はしません。

| 番号 | ブランチ | プルリク |
|---|---|---|
| 0 | `personal/setup` | この番号をコミットしたあと |
| 1〜3 | `personal/ja` | 3を区切ったあと。14を足すときも、ブランチはこのまま |
| 5 | `personal/transport` | この番号のあと |
| 6 | コードを変えたときだけ `personal/ivory` | 変えたとき、この番号のあと |
| 7 | コードを変えたときだけ `personal/export` | 変えたとき、この番号のあと |
| 8〜9 | `personal/midi-edit` | 9のあと |

題名は、コミットの件名と同じく日本語の体言止めにします。ブランチに複数のコミットがあるときは、そのまとまりが分かる題名にします。

## 上流の取り込み

取り込みの前に、自分の変更をコミットしておきます。衝突しやすいのは、画面の文言を直接書き換えたり、上流のコメントをその場で訳したりしたファイルです。カタログと `personal/` と `.cursor/rules/` と `.cursor/skills/` は、上流に無いパスなので衝突しません。
